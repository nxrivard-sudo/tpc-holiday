## Event meaning and limitations

- Meta standard `Lead` here is deliberately a **HoneyBook scheduler-click proxy**, mirroring the existing Google conversion trigger in `tracking.js`. It is not a submitted inquiry, consultation booked, qualified lead, retainer or sale. Label dashboards accordingly; never present its cost as qualified-lead CPA.
- Listener matches only the exact `https://thepicniccollective.hbportal.co` origin, supports dynamically created anchors through event delegation, and counts neither internal navigation nor arbitrary outbound links. Automatic `/go/?d=book` redirects do not emit Lead because there is no link click; pageview is best effort before redirect. A redirect event requires a separately reviewed implementation, not inferred success.
- Pixel script is withheld until consent. Pixel normally collects device/browser and page URL information; do not put email, phone, recipient tokens or other PII in landing-page URLs. Existing email redirect `c`/`ck` tracking must be audited/removed or tracking suppressed on those routes before deployment; no raw customer identifiers are intentionally supplied in this draft. The consent implementation is a prerequisite, not supplied by this file.
- The existing Google tracking stores six attribution parameters and appends them to HoneyBook links. It does not prove fbclid/fbp/fbc storage, cross-domain scheduler capture, CRM attribution, completion events or consent compliance of Google's existing code. Review these separately before paid launch. Do not retrofit email recipient tokens into paid URLs.
- Existing `fbq` from another integration may already have sent events before this script. Confirm a single installation and consent enforcement across all tags; this draft cannot undo a third-party integration.
- Future true qualified-lead/booking events require a verified HoneyBook webhook/API workflow, actual event times and a stable event ID for deduplication if Pixel + Conversions API are both used. No fabricated revenue/value is included.
